# Example — Multilingual / RTL Brand

This example illustrates why multilingual identity work cannot be reduced to translating English artwork.

## Starting situation

A project needs to operate in:

- Arabic
- English
- RTL and LTR interfaces
- bilingual brand lockups
- digital and marketing touchpoints

The user uploads any existing language assets, UI/UX, naming/transliteration rules, and the canonical operating specification.

## Discovery should resolve

Where relevant:

- which language is primary
- whether both scripts appear together or separately
- approved native spelling/transliteration
- markets/regions
- numeral behavior
- bilingual lockup requirements
- tone differences across languages
- font coverage/licensing
- product surfaces where mixed-script strings appear

## Typography

The system should evaluate the actual scripts rather than pairing fonts solely because the Latin specimens look similar.

Important considerations may include:

- relative visual weight
- x-height / Arabic body relationship
- line-height
- punctuation
- numerals
- mixed-script strings
- bold/regular balance
- fallback coverage
- small-size legibility

## RTL is structural

RTL should not be implemented as “mirror every LTR screen.”

The identity/product system should account for:

- hierarchy
- reading order
- alignment
- bidi behavior
- directional icons
- navigation conventions
- composition
- route/progress direction where meaningful

Some graphics should mirror; some must not. The decision depends on meaning, not a blanket transform.

## Logo system

Depending on the brand, production assets may include:

- Arabic/native wordmark
- Latin wordmark
- bilingual horizontal lockup
- bilingual stacked lockup
- symbol-only mark
- small-size variants
- monochrome/reversed versions

The two scripts should feel like one identity rather than a primary logo plus an afterthought translation.

## Real tests

Use real content:

- long Arabic names
- long English names
- mixed numbers
- actual CTA strings
- tickets/cards/documents
- mobile UI
- web layouts

Do not validate multilingual branding using only short placeholder words.

## Key lesson

Localization is part of identity architecture. When language direction and scripts materially affect the experience, they must be designed and validated from the beginning rather than patched on after the visual concept is finished.
